# Runtime Validation & Troubleshooting

[프로젝트 소개로 돌아가기](../README.md)

NO-ROOT에서 다루는 Runtime 디버깅 사례와 상태 검증 관점을 정리합니다. 오류가 나타난 지점에서 출발해 입력, 상태 전이, 시스템 간 연결을 추적하고, 수정 후에는 같은 조건과 관련 생명주기에서 재현 여부를 확인하는 방식으로 접근합니다.

## 사례 공개 상태

아래 두 사례의 원인, 선별한 실제 수정 diff와 회귀 검사 설명을 [수정 전후 근거](evidence/troubleshooting.md)에 공개했습니다. 이 문서의 점검 항목은 조사·검증 관점이며, 새로 실행한 테스트 결과가 아닙니다. 코드의 존재와 실제 Unity 실행 통과는 구분합니다.

| 사례 | 다루는 주제 | 현재 공개 범위 |
| --- | --- | --- |
| **HumanQMissing** | Human 성장 일정과 Validator 계약의 불일치 | 실제 삭제 diff, 원본 커밋, 회귀 검사 설명 |
| **Final Boss progression issue** | Source 결정 이후 갱신되지 않은 진행 Gate | 실제 추가 diff, 콜백·PlayMode assertion 발췌 |

## HumanQMissing

성장 상태와 전투 능력의 연결을 추적하는 사례입니다. 오류 이름만으로 원인을 단정하지 않고, 누락이 처음 관찰되는 상태와 그 이전의 전이 과정을 비교하는 데 초점을 둡니다.

조사·검증 시 확인할 항목:

- 발생 시점의 성장 분기, 능력 보유 상태, 현재 Runtime 상태
- 기대한 능력과 실제 연결된 능력의 차이
- 성장 적용, 상태 복원, 전투 진입 사이의 연결 순서
- 최초 진입, Retry, Restore 각각에서 같은 상태를 재현할 수 있는지
- 수정한 조건과 인접한 성장 조건에서 다른 능력 연결이 유지되는지

**상세 원인 / 수정:** [HumanQMissing 수정 근거](evidence/troubleshooting.md#humanqmissing). 이번 공개 작업에서 실행 결과를 새로 측정하지 않았습니다.

## Final Boss progression issue

최종 보스 진행 문제를 상태 전이의 관점에서 추적하는 사례입니다. 진행 조건 충족, 경로 확정, 저장, 선택 노드 입장 및 보스 관련 동작을 구분해 문제가 발생하는 경계를 확인합니다.

조사·검증 시 확인할 항목:

- 기대하는 진행 상태와 실제 진행 상태의 차이
- 보스 진입 조건을 만족하는 시점과 해당 상태가 저장되는 시점
- 선택 확정 상태와 실제 입장한 노드의 일치 여부
- 보스 관련 동작에 필요한 선행 조건이 전달되는지
- 정상 진행, 저장 후 Restore, Retry에서 진행 흐름이 유지되는지

**상세 원인 / 수정:** [Final handoff gate 수정 근거](evidence/troubleshooting.md#final-handoff-gate). 이번 공개 작업에서 실행 결과를 새로 측정하지 않았습니다.

## Persistence / Retry / Restore 검증 관점

원정 후보와 선택 결과는 재접속·재도전 과정에서도 일관되게 다뤄야 합니다. 다음 항목을 서로 다른 검증 대상으로 구분합니다.

| 검증 대상 | 확인할 동작 |
| --- | --- |
| Deterministic candidate | 같은 생성 조건에 대해 후보가 일관되게 생성되는지 |
| Candidate snapshot | 저장한 후보의 내용과 순서를 Restore 시 유지하는지 |
| Exact-once selection | 반복된 선택 요청이 진행 상태를 중복 반영하지 않는지 |
| Save 경계 | 저장 실패나 중단 이후 확정 상태와 입장 흐름이 어긋나지 않는지 |
| Retry | 재도전에서 초기화할 전투 상태와 유지할 진행 상태를 구분하는지 |
| New Run | 이전 회차의 후보·선택 상태가 새 회차에 남지 않는지 |

이 표는 검증 시나리오이며 테스트 실행 결과표가 아닙니다.

## 사례 기록 방식

**Symptom → Investigation → Cause → Fix → Validation**

재현 조건과 관찰 결과를 먼저 기록하고, 근거가 있는 원인과 수정 사항을 연결합니다. 검증 결과에는 실제로 실행한 환경과 시나리오를 함께 남깁니다. 정적 분석에서 확인한 내용, 자동 테스트 실행 결과, Unity 통합 검증 결과를 구분합니다.

공개 사례를 보강할 때에는 직접 작성하고 공개 가능한 설명·로그·코드 발췌만 선별하며, 원본 private code나 외부 에셋을 자동으로 복제하지 않습니다.
